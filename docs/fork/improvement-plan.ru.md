# Что улучшить в конвейере

Подробная версия с доказательствами в коде лежит в [improvement-plan.md](improvement-plan.md). Ничего из этого ещё не сделано: ты выбираешь пункты, и каждый идёт отдельным PR.

Разобраны все этапы: детекция, OCR, клининг, перевод, тайпинг и финальная проверка.

## По порядку пользы

1. **OCR через API параллельно.** Сейчас нейросеть читает пузыри строго по одному. Если слать 4–8 запросов сразу, гибридный и API OCR станут в несколько раз быстрее. Работы на день.
2. **Набор для проверки качества.** 20–30 твоих страниц с правильным текстом и скрипт, который считает ошибки OCR, пропуски, вылезающий текст, цену и время. Без него нельзя честно сравнить модели и настроить JEV. Сами страницы в репозиторий не кладём.
3. **Пометки «проверь руками» и JEV для OCR.** Общий механизм пометок для всех этапов, и первым его пользователем станет JEV: если локальный OCR и нейросеть прочитали одинаково, текст принимается сразу, а спорные случаи решает JEV или они уходят тебе на проверку.
3а. **Мат и грубость не должны теряться.** Сейчас в задании для нейросети нет требования сохранять мат, и такие строки никак не отслеживаются. План: прямо требовать сохранять силу выражений; находить подозрительные места по словарю (くそ, ちくしょう, てめえ, 死ね и т. п.), по слишком короткому переводу или отказу модели; только эти строки дополнительно переводить через DeepL или Google и сравнивать через JEV. Перевод сам не заменяется: строка помечается, и рядом показывается машинный вариант.
4. **Текст не влезает в пузырь.** Программа уже знает, где текст вылез или стал слишком мелким, но никому не говорит. Нужно показывать такие блоки и добавить кнопку «сократить», которая переводит блок заново с лимитом символов.
5. **Глоссарий проекта.** Имена, пол персонажей, обращения, термины. Для русского это особенно важно: без пола глаголы и прилагательные угадываются заново в каждой главе.
6. **Аккуратная облачная очистка.** Сейчас облачная модель по умолчанию перерисовывает всю страницу целиком, и рисунок вне текста может «поплыть». Лучше вклеивать результат только там, где был текст, а при отказе модерации или остатках букв автоматически переходить к повтору по кускам и затем к локальной LaMa.
7. **Картинки в переводе главы.** Постраничный перевод отправляет нейросети изображение страницы, а перевод главы отправляет только текст. С картинками модель лучше понимает, кто говорит.
8. **Очистка по сложности.** Простой фон заливать или чистить локально, а в облако отправлять только сложные места (звуки поверх рисунка). Так дешевле и быстрее.
9. **Пропущенный текст.** Если детектор не нашёл надпись, её никто не прочитает и не переведёт. Можно раз на страницу спросить нейросеть, какой текст она видит, и пометить то, что детектор пропустил.
10. **Проверка перевода через JEV.** Сохранён ли смысл, совпадают ли пол и обращения с глоссарием, не остался ли японский текст. Перевод JEV только помечает, сам ничего не переписывает.
11. **Порядок чтения японских страниц.** Вернуть проверки из старого коммита и помечать страницы, где порядок неочевиден.
12. **Более точные маски текста.** В проекте уже есть модель для попиксельной маски текста, но конвейер её не использует. Это интеграция модели, поэтому сначала сравнение и обсуждение.
13. **Финальная проверка перед экспортом.** Сейчас её нет. Нужен один список по главе: непроверенные пометки, пустые переводы, японские символы в русском тексте, вылезающий или слишком мелкий текст, остатки букв после очистки, пропущенные надписи. Всё это считается бесплатно. По желанию можно добавить нейросеть, которая смотрит на готовую страницу рядом с исходной. Экспорт при этом не блокируется.

## Что выяснилось про JEV

- Это модель TypeSafe AI «System One» (`jev-1.13.0`). Она отвечает выбором из вариантов, вероятностью «да/нет» или оценкой по шкале.
- **Она принимает только текст, картинки не видит.** Поэтому читать картинку будет нейросеть-OCR, а JEV сравнивает варианты по тексту и числам: уверенность локальной модели, совпадение вариантов, длина текста относительно размера пузыря.
- Адрес API в старом коммите был неверный. Перед написанием клиента нужно сверить актуальный адрес по документации TypeSafe, потому что один из адресов объявлен устаревающим.
- Стоит очень дёшево: около $0.04 за миллион входных токенов, ответ бесплатный.
- В приложении JEV будет выключен по умолчанию и включаться переключателем в настройках. Ключ хранится только в системном хранилище паролей.
