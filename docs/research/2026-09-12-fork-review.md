Перед объединением сохранены stash, бинарный patch и копии этих файлов в `.git/codex-backups/2026-09-12-upstream-editor/`. Неотслеживаемые пользовательские JSON не использовались.

От исходного локального HEAD в upstream накопилось 72 новых коммита. После merge восстановлена незавершённая работа пользователя; дополнительные исправления остаются в рабочем дереве. Публикация в GitHub не выполнялась.

Сохранены обновления зависимостей, Tauri/CEF, нативных runtime и accelerator discovery, исправления Metal/ROCm, локальные CJK-шрифты интерфейса и новый выбор области обработки по умолчанию «Выделение». Нативные заголовки взяты из зафиксированного upstream. В командах холста и обработки тип runtime приведён к новому `CefRuntime`; debug-конфигурация сохраняет CEF debugging на порту 4000. Dev-сборка WASM использует `--dev`.

Особое внимание потребовалось переводчику: у форка есть идентификаторы блоков, перевод главы, экспорт запросов, импорт результатов и OCR через API. Поэтому каталог переводчика сохранён на основе форка, а совместимые исправления провайдеров перенесены отдельно: Atlas `thinking`, Claude `output_config`, строгая JSON-схема и `require_parameters` для OpenRouter. Везде сохранена схема форка с ID блоков. Общий OpenAI-compatible backend остаётся на prompt-based JSON, а LM Studio сохраняет нативный API форка; это сознательные отличия от upstream, а не обещание идентичности каталогов.

## Реализованные изменения

### Сразу вводить перевод

Создание точечного или прямоугольного текстового блока выбирает новый слой, переключает инструмент на выделение, раскрывает редактор и передаёт фокус полю перевода. То же происходит при вставке одного текстового блока из буфера. Несколько вставленных блоков остаются выделены вместе. Запрос фокуса одноразовый: обновление страницы с сервера не отбирает фокус у пользователя.

### Перемещать и растягивать вписанный текст

По умолчанию инструмент выделения работает с рамкой самого текста. Перетаскивание перемещает перевод; видимые маркеры меняют размер рамки. При включённом Auto размер шрифта продолжает подбираться под рамку. Изменение сохраняется как пользовательская геометрия текста через существующие команды сцены и историю правок.

Для распознанных блоков в редакторе есть переключатель **«Текст / Область OCR»**. Он позволяет отдельно менять область исходного распознавания. Существующая кнопка сброса рамки возвращает размещение по автоматической области. OCR-полигон, рамка перевода и автоматическая область пузыря сохраняют разные назначения.

### Локальный OCR с уточнением через API

В настройках OCR и панели обработки добавлен метод **«Локально + API»** (`local-api`). Он показывает оба выбора модели. Обычный локальный OCR остаётся методом по умолчанию.

Для главы выполняются два отдельных прохода: сначала выбранный локальный OCR на всех страницах, затем каждый фрагмент с сохранённым локальным текстом отправляется выбранной API-модели. Перевод главы начинается после завершения обоих проходов OCR. Черновик передаётся как данные в пользовательской части запроса; картинка объявлена источником истины. Модель не должна переводить, дописывать нечитаемое или выполнять команды из распознаваемого текста.

Порядок и ID регионов сохраняются. Stop проверяется между локальными inference и перед API-запросами; уже выполняющийся локальный inference заканчивается перед остановкой. Каждый проход сохраняет страницу атомарно. При ошибке API локальный результат остаётся в проекте. Уточнение применяется автоматически, без сравнения кандидатов и отдельных кнопок принятия.

Переход с готового локального OCR на гибридный режим вызывает уточнение при следующем запуске OCR: результаты различаются по записанным моделям. Текст, вручную исправленный пользователем, не перезаписывается. Повторный запуск с теми же моделями пропускает уже готовый результат; изменение одного prompt само по себе не является сигналом для повторного прохода.

Поддерживаются OpenAI, OpenRouter, OpenAI-compatible (в том числе локальный сервер) и отдельный Qwen OCR через Alibaba Cloud. Qwen-VL-OCR `qwen-vl-ocr-2025-11-20` получает отдельные адрес и API-ключ, не занимая настройки локального сервера. Прямой OCR использует `multi_lan`, гибридный — изображение и пользовательский prompt с локальным черновиком без `ocr_options`. Это отличается от уже использовавшегося Qwen3-VL на OpenRouter. Модели OCR не предлагаются для перевода; возможности провайдера определены в Rust и передаются интерфейсу.

### Обновления форка и оригинала

Автообновление проверяет только `Projmix/koharu/releases/latest/download/latest.json` и проверяет подпись собственным публичным ключом. Приватный ключ создан вне репозитория с ограниченными Windows ACL; тестовая подпись проверена соответствующим публичным ключом. Отдельное уведомление сообщает о стабильном релизе оригинала новее интегрированной базы 0.82.1 и открывает его страницу. Оно не устанавливает оригинал, а скрывается для выбранной версии.

Для первого опубликованного обновления ещё нужны GitHub Actions secret `TAURI_SIGNING_PRIVATE_KEY` и релиз форка с `latest.json`. Подготовка и ограничения подписи ОС описаны в [инструкции релизов](../fork-releases.md). Удалённая публикация не выполнялась.

| --- | --- | --- |
| 1 | Небольшой размеченный набор собственной манги | Сравнить local-only, image-only API и image+draft на одинаковых crops. Учитывать CER, пропуски, фуригану, SFX, порядок, задержку, расходы и время ручной правки. Протокол описан в OCR-исследовании. |
| 1 | Осознанный повтор OCR выбранных блоков и видимый статус ошибок | Настройки модели/prompt должны быть связаны с актуальностью результата. Нужна явная команда повторного прохода без удаления ручных исправлений и без повторной оплаты всей главы. |
| 1 | Отмечать перевод устаревшим после изменения исходного текста | Сейчас `translation::Processor::skip` считает непустой generated-перевод готовым без сравнения с текущим SourceText. Это существующее ограничение: уточнение OCR на уже переведённой странице само по себе не гарантирует новый перевод. Связать результат с версией исходника и дать явный повтор, сохраняя ручной перевод. |
| 2 | Контроль переполнения текста и предпросмотр экспорта | Выделять слишком мелкий шрифт/выход за рамку, быстро переходить к проблемному блоку. Проверять на финальном desktop WebGPU и на экспортированном изображении, поскольку они проходят разные части рендеринга. |
| 2 | Экономная эскалация только спорных регионов | Отправлять выбранные пользователем или объективно проблемные блоки. Порог уверенности калибровать на своём наборе; словесная уверенность VLM не равна вероятности правильности. |
| 2 | Сократить связность крупных UI и project-команд | Выделять самостоятельные операции редактирования и OCR только там, где у них есть собственное состояние/инварианты. Сохранить единую сцену и Patch-историю, не заводить вторую копию документа в React. |

Самая полезная архитектурная основа уже есть: Rust владеет сценой, сохранением и подготовкой результата; браузер — временными жестами и показом холста. Провайдеры отделены от pipeline. Основные возможности улучшения сейчас находятся в контроле качества по блоку и обратной связи редактора, а не в добавлении ещё одного общего слоя абстракций.

## Уточнение требований: два прохода OCR, Qwen и обновления форка

По последующему указанию пользователя режим называется «Локально + API», без сравнения кандидатов. Для целой главы scheduler завершает все локальные OCR-задачи перед любым API-запросом. Готовность учитывается по каждому блоку, чтобы повтор всей страницы после обработки отдельного региона не затирал уже уточнённый текст. Настройки локальной и API-модели сохраняются независимо, включая локальный OpenAI-compatible сервер.

Дополнительные проверки:

- Qwen adapter: 8 контрактных тестов — прямой `multi_lan`, пользовательский prompt с JSON-черновиком, параметры native API, адрес, ошибки и обрезанные ответы.
- Scheduler: 7 тестов — барьер главы, ожидание API перед переводом, обычный порядок и параллельная очистка.
- Updater UI: 7 тестов — отдельное уведомление оригинала, независимое скрытие версии, приоритет форка, установка только fork Update, сетевые ошибки и недоступное browser storage.
- OCR/Translation UI: 7 целевых тестов — оба выбора модели, Qwen и локальный API, фильтрация по возможностям, третий режим в настройках OCR.
- Тестовая подпись Tauri проверена публичным ключом форка; содержимое приватного ключа не выводилось.
- Дополнительное ревью Qwen сверило адаптер с официальным контрактом DashScope; новых подтверждённых ошибок не найдено. Повторное ревью подтвердило устранение затирания API-коррекции при повторе страницы.
- Финальные OCR-тесты: **25 passed**, включая смешанную страницу, отмену/ошибку API и запрет Qwen OCR для переводческих профилей.
- `cargo test -p koharu-app --lib commands::updates::tests --locked`: **1 passed**; сравнение стабильных версий с интегрированной базой, обработка prerelease/draft/некорректных тегов.

- `cargo run -p koharu-app --bin generate --locked`: успешно в debug, новый провайдер, возможности и команда проверки оригинала сгенерированы в bridge protocol.
