# Ручной перевод главы

Этот режим позволяет переводить распознанную главу в любом внешнем чате или редакторе. Выбор модели, провайдер и ключи API в Koharu для него не нужны.

1. Выполните детекцию и OCR, проверьте исходный текст и порядок чтения.
2. В области обработки выберите весь проект и нажмите **Экспорт для ручного перевода (ZIP)**.
3. Распакуйте архив. В нём два файла: `prompt.txt` с инструкцией и `chapter.json` с исходными текстами в порядке страниц, группами реплик и контекстом.
4. Вставьте содержимое `prompt.txt` в выбранный чат и приложите `chapter.json`.
5. Сохраните полученный JSON как `translation.json` в UTF-8. Нажмите **Импорт переведённого JSON** и выберите этот файл.

В ответе должны быть `project_id`, `target_language` и массив `translations`. Для каждой записи нужны только:

- `id` — идентификатор блока, скопированный из исходного файла;
- `source_text` — исходный текст без изменений, включая пробелы и переносы;
- `translated_text` — готовый перевод.

Поля `page_id`, `region_id`, настройки модели, обёртка ответа API и Markdown в ответ не добавляются. Идентификатор `id` уже однозначно связывает перевод с блоком. Порядок записей в ответе может отличаться от исходного.

Импорт проверяет проект, язык перевода, полноту списка, уникальность и известность ID, неизменность исходных текстов и отсутствие пустых переводов. Проверка всего файла выполняется до изменения проекта. Если есть ошибка, ничего не импортируется. Успешный импорт можно отменить обычной командой отмены.

Существующие переводы, отредактированные вручную в Koharu, передаются как контекст и не перезаписываются импортом. Изменение OCR или набора блоков после экспорта может потребовать нового экспорта.

Уточнение OCR через API получает вырезанные детектором области. Если OCR прочитал вертикальный японский текст поперёк строк, исправьте порядок исходного текста до экспорта: перевод не восстанавливает надёжно потерянный порядок чтения.
